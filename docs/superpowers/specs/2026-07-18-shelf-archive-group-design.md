# 书架 archive 分组设计

## 目标

在书架视图的“书籍类型”选项中新增“仅分组”。选择后，书籍按照微信读书 Shelf API 返回的 `archive` 书单分组展示；分组内使用插件设置中的“书架排序”；不属于任何书单的条目归入最后的“未分组”。

## 需求范围

- 新增 `仅分组` 类型筛选值。
- 使用 Shelf API 返回的 `archive[].name` 作为分组标题，使用 `archive[].bookIds` 关联书架条目。
- 一本书属于多个 `archive` 时，在每个对应分组中显示一次。
- 分组顺序沿用 API 返回顺序，`未分组` 始终位于所有分组之后。
- 搜索和书籍状态筛选先于分组执行。
- 每个分组内沿用现有排序规则：按最近阅读或按书名。
- 现有“全部图书”和“只有书籍”的按活动年份分组行为保持不变。

## 数据模型与缓存

在 API 层增加可选的 archive 响应类型：

```ts
interface RawShelfArchive {
  name: string;
  bookIds: string[];
}
```

`RawShelfResponse` 增加可选的 `archive` 字段。同步书架时，将其规范化后写入 `ShelfCache`：

```ts
interface ShelfArchive {
  name: string;
  bookIds: string[];
}
```

`ShelfCache.archives` 采用可选字段，以兼容已有的旧缓存。新同步写入的缓存始终包含 archive 数组；旧缓存缺少该字段时按空数组处理，不需要迁移版本号。

## 分组流程

`filterAndGroupShelf` 继续先执行类型、状态和搜索过滤。

当类型为 `grouped` 时：

1. 按缓存中的 archive 顺序遍历分组。
2. 对每个 archive，按 `bookIds` 找出当前过滤结果中的条目。
3. 同一 archive 内同一个条目最多加入一次；条目可加入多个不同 archive。
4. 记录所有至少匹配一个 archive 的条目。
5. 将未被任何 archive 匹配的过滤结果放入 `未分组`，并追加到分组列表末尾。
6. 对每个非空分组调用现有组内排序逻辑。

未知的 `bookId` 不生成空卡片；过滤后没有条目的 archive 不显示。若所有条目都被搜索或状态过滤排除，视图继续使用现有的空结果提示。

旧缓存没有 archive 数据时，`仅分组` 会将所有通过其它过滤条件的条目显示在“未分组”中；下一次同步后即可恢复真实分组。

## 视图行为

“书籍类型”下拉框增加：

```text
仅分组
```

分组标题直接使用 archive 名称；“未分组”不追加年份后缀。年份分组仍沿用当前的年份标题显示逻辑。

## 测试策略

增加纯状态逻辑测试，覆盖：

- `grouped` 只显示按 archive 关联后的分组结果。
- 一本书同时出现在多个 archive 时，在多个分组中出现。
- 未归属条目进入“未分组”，且“未分组”位于最后。
- 分组内按最近阅读排序和按书名排序。
- 搜索和状态过滤在 archive 分组之前生效。
- 没有 archive 数据的缓存将条目归入“未分组”。

增加同步服务测试，确认 Shelf API 返回的 archive 被保存到缓存，并保留现有书籍、有声书同步行为。

更新现有缓存测试夹具，为旧缓存验证可省略 archive 字段；新建缓存结果验证 archive 数据。

## 非目标

- 不新增网络请求；分组数据随现有 Shelf API 请求获取。
- 不改变现有按年份分组的默认视图。
- 不改变或持久化用户对 archive 分组的编辑。
- 不去重跨 archive 分组的书籍卡片。
